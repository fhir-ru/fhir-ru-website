Используется разделение документов по образцу `med_quality_runtime`.

| Каталог | Назначение |
| --- | --- |
| `architecture/` | Устойчивые требования к сайту и архитектуре |
| `decisions/` | Принятые решения и предложения на рассмотрение |
| `procedures/` | Правила разработки, проверок и публикации |
| `initiatives/` | Ограниченные цели работ: scope, status, backlog, log |

## Источник истины

Требования к продукту не хранить только в backlog, а текущий прогресс —
в архитектурной спецификации. При изменении решения обновлять ADR и связанные
требования, затем статус, backlog и журнал. В первой спецификации подтверждённые
направления отделены от предлагаемых деталей. Новое предложение не становится
утверждённым требованием автоматически.
